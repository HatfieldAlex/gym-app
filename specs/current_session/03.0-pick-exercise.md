# 03.0 — Pick and hold an exercise

**Goal:** inside an active session, choose an exercise from the catalogue and
hold it: from then on the section says which movement is being recorded, until
the user lets go of it.

Needs chunk 02.1. Nothing is written to the API in this chunk.

## Read first

- `CurrentSession.jsx` as chunk 02.1 left it
- [ExerciseCatalogue.jsx](../../frontend-web/src/pages/ExerciseCatalogue.jsx) — how the catalogue is fetched
- [00-context.md](00-context.md), assumption A10 — the hold is client-side

## Build

All of this replaces the placeholder paragraph in the **Record new exercise**
section chunk 02.0 left in place. That section and its `<h2>` already exist: do
not add a second heading, and do not move the section.

1. **Exercise options.** Load the catalogue with a second `useLoad` —
   `api.list('exercises/')`. It is read-only reference data, already ordered by
   name, so fetch it once and do not sort it again. Render it as a `<select>`
   starting on an empty "Choose an exercise" option, disabled until the
   catalogue is in.

2. **A failed catalogue gets its own line.** `<Status>` speaks for the session
   load (chunk 02.0); a catalogue that will not load needs a short message of
   its own, and must not be able to look like "no session".

3. **Choosing holds the exercise.** The dropdown is replaced by a line naming
   what is being recorded — "Recording Bench press". While an exercise is held
   the section is about that one movement: the dropdown is gone, not merely
   ignored. This is the seam every later chunk hangs off — the sets in 03.2 and
   the form in 03.5 both belong to the held exercise.

4. **Letting go.** A small **Change exercise** control returns the section to
   the dropdown, on the empty option. Deliberately small: it is the way out of a
   mis-tap, not something to hit with a thumb mid-set (A8).

5. **The hold is client-side (A10).** Choosing an exercise POSTs nothing — no
   `PerformedExercise` exists until there is a set to put in it (03.5). A
   refresh therefore returns to the dropdown, with everything logged still
   logged. That is the accepted cost, not a bug: say so in a short comment
   rather than building around it.

6. **Style.** Add to the `/* Current session */` section chunk 02.1 opened in
   [styles.css](../../frontend-web/src/styles.css) — enough to make the held
   exercise read as its own block. Ergonomics are chunk 07.

## Done when

- The dropdown lists every catalogue exercise by name and starts on "Choose an
  exercise".
- Choosing one replaces the dropdown with that exercise's name; **Change
  exercise** brings the dropdown back, on the empty option.
- Choosing an exercise creates nothing:
  `GET performed-exercises/?training_session=<id>` returns exactly what it
  returned before.
- A refresh with an exercise held returns to the dropdown, with the session and
  everything logged in it unchanged.
- With the catalogue endpoint failing, the section shows a short message and the
  rest of the page is unaffected.

## Do not

- Create a `PerformedExercise` when an exercise is chosen — 03.5 creates it with
  the first set.
- Add weight, reps or a **Log set** button — 03.5.
- List the sets of the held exercise — 03.2.
- Rename, duplicate or reorder the two sections chunk 02.0 established, or touch
  the list chunk 02.1 built.
- Let the user create a catalogue entry from here; `exercises/` is read-only.
- Write the held exercise to `localStorage` to survive a refresh.

## What the user sees

The **Record new exercise** section stops being a placeholder and becomes one
question.

- **A dropdown appears** in place of the placeholder line, listing every
  exercise in the catalogue by name and starting on "Choose an exercise".
  Nothing else — the section asks one thing.
- **Choosing an exercise commits to it.** The dropdown gives way to a line
  saying what is being recorded — "Recording Bench press" — and the section is
  about that movement from then on, the way the tab as a whole is about the
  running session. There is no half-state where a choice sits unremarked in a
  widget.
- **Getting out is possible but quiet.** A small **Change exercise** control puts
  the dropdown back. It is small on purpose: it is for a wrong tap, not for the
  hand that is mid-workout.
- **Nothing is recorded yet.** Holding an exercise records no workout — it says
  what is about to be recorded. A refresh returns to the dropdown, and anything
  already logged in the session is still there below.

What the user cannot do yet: log anything against the held exercise. The weight
and reps go in at 03.5, and the sets already logged against it appear at 03.2.
