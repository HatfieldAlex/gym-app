# 02.1 — The live list

**Goal:** everything logged in this session, visible below the **Record new
exercise** section, and up to date the moment anything is added to it.

Needs chunk 02.0. Rendering only — no requests are made in this chunk.

It comes before the form on purpose: built the other way round, the writes in
chunk 03.5 would have nowhere to show and could only be checked with a `curl`.
Seed a session's sets through the API (or the admin) to see this list working.

## Read first

- `CurrentSession.jsx` as chunk 02.0 left it
- [TrainingSessionDetail.jsx](../../frontend-web/src/pages/TrainingSessionDetail.jsx) — this list is the same data, rendered smaller

## Build

1. Inside the **Completed exercises** section chunk 02.0 left in place — the
   lower of the two, below **Record new exercise** — replace the placeholder
   paragraph with an `<ol>` of `session.performed_exercises`. The API already
   returns them in the order the exercises were first started, and their
   `performed_sets` in the order they were logged, so **sort nothing and group
   nothing**: the API's order is the order they were trained, and the nesting is
   the grouping.

2. Each exercise is one `<li>`, numbered by its position — "1. Bench press",
   "2. Squat" — as `PerformedExercise` in
   [TrainingSessionDetail.jsx](../../frontend-web/src/pages/TrainingSessionDetail.jsx)
   already renders it — but as an `<h3>`, since the section heading above it is
   the `<h2>`. Under that heading its sets are numbered 1, 2, 3… by
   position in their own array. Show weight and reps per row — "60 kg × 8", or
   just "8 reps" where the weight is null. Do not print `null` or `0` for a
   missing weight.

3. **A set is one row**, not a table cell that needs a header to read. Keep each
   row on one line and tall enough to tap; chunk 05 adds controls to the end of
   it, so leave the right-hand end of the row free.

4. **Empty states, two of them.** With nothing logged at all, the section keeps
   its heading and shows one quiet line — "No exercises logged yet." — in place
   of the `<ol>`. An exercise that has no sets of its own keeps its numbered
   `<li>` and shows "No sets logged yet." under it; chunk 05 can produce one by
   deleting the last set. Follow the empty-state wording the other pages use.

5. Read it straight from `session` — the state chunk 02.0 loads and every later
   chunk writes into. Once chunk 03.5 lands, a new set appears here the moment
   its POST resolves, with nothing wired up between them, because both read that
   same state. Build for that now; there is nothing to confirm until then.

6. Style it in `styles.css` under a new `/* Current session */` section, next to
   the other per-page sections. Reuse the existing `.sets` and `.performed`
   conventions where they fit rather than inventing a parallel set of names.
   Ergonomics come in chunk 07 — plain and correct is enough here.

## Done when

- With two exercises' sets seeded through the API, they show as 1 and 2 in the
  order they were first logged, each with its own sets numbered from 1.
- The "Completed exercises" heading is there before anything is logged, with the
  quiet empty line under it, and the **Record new exercise** section stays above
  it throughout, still holding chunk 02.0's placeholder line.
- A bodyweight set (null weight) reads sensibly with no stray `null`, `—` or `0`.
- A refresh reproduces the list identically from the API.
- The list is readable on a 375px-wide viewport without sideways scrolling.

## Do not

- Re-sort, de-duplicate or regroup what the API returned.
- Add per-set edit or delete controls — chunk 05.
- Add totals, volume, PR badges or a set-count summary.
- Introduce a second copy of the logged data in state.

## What the user sees

The **Completed exercises** section fills in, so the workout becomes visible as
it is being done. Nothing new can be *done* in this chunk — it is what the user
sees, not what they can act on.

- **Everything logged so far is listed in the lower section**, in the order the
  exercises were first started: "1. Bench press", "2. Squat", and under each one
  its sets numbered 1, 2, 3… in the order they were logged.
- **A set reads as one line** — "60 kg × 8", or "8 reps" for a bodyweight set.
  A set with no weight reads cleanly; no `null`, no `0 kg`, no stray dash.
- **New sets will appear instantly.** Once the form above can log one (chunk
  03.5), a set lands at the bottom of its exercise immediately — no refresh, no
  waiting for the list to catch up.
- **Before anything is logged**, the heading is still there with one quiet line
  under it — "No exercises logged yet." — so the section never looks broken or
  half-drawn.
- **An exercise with no sets** (possible once chunk 05 allows deleting) keeps its
  numbered heading and says "No sets logged yet." under it, rather than
  disappearing.
- **A refresh reproduces the list exactly**, because it is read back from the
  server rather than remembered in the page.
- **It fits a phone screen** — readable at 375px wide with no sideways
  scrolling.

Sets still cannot be corrected or removed from here; each row leaves room at its
right-hand end for the controls chunk 05 adds.
