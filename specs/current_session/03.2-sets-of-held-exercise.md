# 03.2 — The sets of the held exercise

**Goal:** while an exercise is held, the sets already logged against it in this
session are listed under its name — where they were logged, not only in the
section below.

Needs chunk 03.0. Rendering only — no requests are made in this chunk.

## Read first

- `CurrentSession.jsx` as chunk 03.0 left it
- [02.1-live-list.md](02.1-live-list.md) — the section below, and the wording a
  set line already uses

## Build

1. **Find the block.** The held exercise's sets are
   `session.performed_exercises.find(p => p.exercise_definition === heldId)`
   and its `performed_sets`. A held exercise with no block is the ordinary case,
   not an error: it has simply not been trained yet in this session.

2. **In the order the API gave them.** `performed_sets` arrives in the order the
   sets were logged, so sort nothing and number by position — 1, 2, 3….

3. **One line per set, worded exactly as chunk 02.1 words it** — "60 kg × 8", or
   "8 reps" for a set with no weight. Reuse that formatting rather than writing
   a second phrasing for the same fact; the two lists must not disagree about
   what a set reads like. Never print `null`, `0` or a stray dash for a missing
   weight.

4. **Empty state.** A held exercise with no sets yet says "No sets logged yet."
   — the same line chunk 02.1 uses for an exercise with none.

5. **The boundary with 02.1.** This list is the held exercise and nothing else;
   the whole workout stays in **Completed exercises** below, untouched. Same
   data, two renderings, on purpose: one is where the user is working, the other
   is what they have done. Both read the same `session` state — do not keep a
   second copy of anything.

**Checking it before there is a way to log.** Nothing on the page can create a
set until 03.5. POST two sets against this session with `curl` (or the admin),
refresh, hold that exercise, and they appear.

## Done when

- With sets seeded through the API, holding that exercise lists them under its
  name in the order they were logged, numbered from 1.
- Holding an exercise not yet trained in this session shows "No sets logged
  yet." and nothing else.
- A set logged with no weight reads sensibly, with no `null`, `0 kg` or dash.
- **Change exercise**, then holding it again, shows the same list.
- The **Completed exercises** section renders exactly as chunk 02.1 left it.

## Do not

- Add per-set edit or delete controls — chunk 05.
- Add totals, volume, a set count or PR badges.
- Change, re-sort or duplicate the list chunk 02.1 built.
- Introduce a second copy of the logged data in state.
- Fetch anything: every set on this page is already in `session`.

## What the user sees

The held exercise stops being a name and becomes a record of what has been done
to it so far.

- **The sets of the held exercise are listed under its name**, numbered 1, 2,
  3… in the order they were logged — so the answer to "how many have I done, and
  at what?" is in the place the user is already looking, not in the section
  below.
- **They read as they do everywhere else** — "60 kg × 8", or "8 reps" for a
  bodyweight set. The same set says the same thing in both lists.
- **An exercise with nothing logged says so** — "No sets logged yet." — rather
  than showing an empty gap.
- **Coming back to an exercise shows its history.** Choosing something trained
  earlier in the session brings its sets up with it, so returning to a movement
  visibly continues it rather than starting over.

Nothing new can be *done* here: this is what the user sees, not what they can
act on. Logging is 03.5.
