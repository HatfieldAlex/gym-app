# 03.5 — The expression in a finished session's table

**Goal:** the fourth screen AGREED 7 lists. A past session's set table shows the
same working the zone now shows, in the one column it belongs in.

Needs chunk 03.0 for `sets.js`, and chunk 02 for the two fields on the performed
exercise — this page has **no catalogue in hand** and never fetches one. One
file, plus one option on one function.

## Build

1. **`weightText` learns to leave the unit off.** A third argument —
   `weightText(weightKg, loading, { unit = true } = {})` — because this cell sits
   under a header that already says **Weight (kg)** and `= 110 kg` under it is
   the unit twice. Everywhere else keeps the unit, and keeps it by default.

2. **The weight cell shows the expression when there is one, and is otherwise
   left completely alone.** In `PerformedExercise`'s cell render at line 70:

   - `weight_kg` column, and `weightText(…, { unit: false })` gives a string
     back → render that string.
   - anything else — a different column, a bodyweight set, an unset movement, a
     collapsed `0 / 1`, a total below its bar → render exactly what line 70
     renders today, `set[column.key] ?? '—'`.

   The second branch matters more than the first. Today the cell shows the raw
   decimal string, `110.00`, and for every set that has no expression to show it
   must keep showing `110.00` — same trailing zeros, same dash for an empty
   measure. A set this feature has nothing to say about is a set this feature
   does not touch.

3. **The loading comes off the performed exercise**, `loadingOf(performed)`,
   computed once per exercise rather than once per cell. Nothing on this page
   fetches the catalogue, and nothing in this chunk starts (W2, and the reason
   `exercise_name` already exists at observations/serializers.py:45).

4. **`SET_COLUMNS` does not change.** No new column, no per-side column, no
   `Bar` or `Sides` column. Five measures is what a set records; how it was
   loaded is a property of the movement, and the movement's name is already the
   heading over the table.

5. **The column-dropping rule at line 44 does not change either.** It asks
   whether any set filled that measure in, and a bodyweight set still leaves
   `weight_kg` null, so a bodyweight exercise still shows no weight column at
   all. Nothing about the loading makes a null weight worth a column.

## Done when

- A past session containing **deadlift** shows, under **Weight (kg)**,
  `20 + 2 × 45 = 110` where it used to show `110.00`, with **Reps** beside it
  unchanged.
- The same session's **lat pulldown** rows still show `50.00`, and **pull ups**
  still shows no weight column at all.
- A **seated calf raise** row — the movement left unset — still shows `45.00`,
  the same characters it showed before this chunk.
- A row logged below its own bar still shows its bare total.
- The exercise headings, the set numbering, the exercise/set counts at the top,
  the "No sets recorded." line and the back link are all untouched.
- The zone still reads exactly as chunk 03.0 left it: the `unit` option changed
  a default-argument path, not a rendering.
- A reload shows the same thing.

## Do not

- Fetch `exercises/` on this page, or add a second request of any kind (W2).
- Add a column to `SET_COLUMNS`, or a per-side column anywhere.
- Change what an unexpressible set renders — including its trailing zeros
  (step 2).
- Touch `CurrentSession.jsx` beyond nothing at all; if `sets.js` needed a
  change, that change is the `unit` option and only that.
- Make this page editable in any way. Fixing an old set is this page's
  long-standing non-job, and it stays that way.
- Touch anything under `backend/`.

## What the user sees

**A finished workout shows the same working as a live one.**

Open a session from the history list and the deadlift table now reads
`20 + 2 × 45 = 110` under **Weight (kg)** — what was on the bar and what it came
to, instead of a total to be reverse-engineered. The stacks, the bodyweight
movements and anything the app has not been told about read exactly as they read
before, down to the trailing zeros.

That is every screen in AGREED 7 done. From here on the feature stops being
about reading and starts being about typing.
