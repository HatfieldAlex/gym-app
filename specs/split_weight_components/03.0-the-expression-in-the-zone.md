# 03.0 — The expression, everywhere the current session reads a set

**Goal:** a set stops reading `140 kg × 8` and starts reading
`20 + 2 × 60 = 140 kg × 8` — in the zone's set list, in the "Last time" column
beside it, and in the Earlier lines under it. The arithmetic gets one module and
one home, which every chunk after this imports.

Needs chunk 02. Frontend only, and **read-only**: nothing about entering a set
changes here, so the boxes still take a total. That is chunk 04.

## Build

1. **A new module, `frontend-web/src/sets.js`.** Not a component and not a hook:
   four pure functions and the comments explaining the rules they encode. It
   sits beside `api.js` and `hooks.js` because three pages will import it, and
   because the rounding rule needs exactly one home.

   | Export | Takes | Gives back |
   |---|---|---|
   | `loadingOf(performed)` | a performed exercise from the API | `{ bar_kg, sides }`, read off `exercise_bar_kg` / `exercise_sides` |
   | `perSide(weightKg, loading)` | the stored weight (a decimal string or null) and a loading | the exact per-side weight as a string, or `null` when there is none to give |
   | `weightText(weightKg, loading)` | the same | the weight half of a line — `"20 + 2 × 60 = 140 kg"`, `"25 + 50 = 75 kg"`, `"50 kg"` — or `null` for a bodyweight set |
   | `setSummary(set, loading)` | a set and a loading | the whole line: `"20 + 2 × 60 = 140 kg × 8"`, `"8 reps"`, `""` |

   `loading` is `{ bar_kg, sides }` and nothing more, so a catalogue entry can be
   passed straight in (the zone has one in hand at CurrentSession.jsx:495) and a
   performed exercise goes through `loadingOf` first. `loading` may be `null`,
   `undefined`, or an object with nulls in it: all three mean unset, and all
   three come out as today's plain total.

2. **The rules are 00-context's table, verbatim**, and each one gets a comment
   saying *why*, in the register the rest of this file is written in. The four
   that will otherwise be quietly "simplified" away later:

   - **A null `weight_kg` is bodyweight** and shows as it does today — `8 reps`,
     no expression, whatever the exercise is configured as (W9). It is not
     `0 + 2 × 0`.
   - **Unset is not zero.** Either column null means the exercise has never been
     asked, and the row reads exactly as it read yesterday (AGREED 5).
   - **The number is exact, never rounded** (W3). `(107.55 − 20) / 2` shows as
     `43.775`. Comment the reason: the expression has to equal the weight that
     was actually lifted, and a tidy `43.78` describes a set nobody did. At most
     three decimals is not a cap that can bite — a two-decimal total halved is
     three decimals exactly — but strip trailing zeros so `45.00` reads `45`.
   - **A total below its own bar falls back to the plain total** (W4). You will
     see this in the seeded data: an early-week barbell curl at 17.5 kg against
     a 20 kg bar reads `17.5 kg × 10`, not `20 + 2 × −1.25`.

   The collapses, also from that table: `bar_kg` 0 with `sides` 1 gives the plain
   `50 kg` (AGREED 7); `sides` 1 with a bar gives `25 + 50 = 75 kg`, dropping the
   `1 ×` and keeping the bar (W8).

3. **Arithmetic in integer thousandths** (00-context).
   `Math.round(Number(value) * 1000)` in, formatting out; no floating-point sum
   reaches a screen. Thousandths and not hundredths because halving a two-decimal
   total is exactly where a third decimal appears, and it must stay an integer
   for the whole trip. A one-line comment on each point is enough — the reason is
   `0.1 + 0.2`, and the reader will know it.

4. **`setSummary` leaves CurrentSession.jsx.** Delete the function at 25–29 and
   import it from `sets.js`. Its docstring goes with it, extended rather than
   rewritten: the `weight_kg` decimal-string note and the "no weight is not zero
   weight" note are both still true and both still needed.

5. **A row is told what it is a set of.** `SetRow` and `SetList` each take a new
   `loading` prop and pass it down; `SetRow` uses the one value for **both**
   cells it renders, because last time's set and this session's set are the same
   movement by construction — the comparison would be meaningless otherwise.
   Say that in a comment, since the two cells otherwise look like they might want
   two different loadings.

6. **The three callers, each given the right loading:**

   - The zone's list (the `<SetList>` at 985–990): `loading={held}` — the
     catalogue row itself, already in hand at line 495, `bar_kg` and `sides` on
     it directly.
   - Completed exercises (`PerformedExercise` at 414–424, its `<SetList>` at
     421): `loading={loadingOf(performed)}`.
   - The Earlier lines at 1014:
     `performed.performed_sets.map((set) => setSummary(set, loadingOf(performed)))`,
     still joined with `', '`.

7. **Nothing else moves.** Column widths, the `data-none` dashes, the numbering,
   the Edit and Delete controls, `parseEntry`, the log form and the two boxes are
   all exactly as they were. A longer string in `.set-measures` will make some
   rows wrap at phone width; leave it. Chunk 08 is where the columns are given
   room, and doing it here would mean doing it twice.

## Done when

With `make dummy-data` run, so the backfill of chunk 01 has movements to act on:

- In the zone, holding **deadlift**, this session's sets and Last time's both
  read `20 + 2 × 45 = 110 kg × 5` rather than `110 kg × 5`.
- Holding **lat pulldown** (`0 / 1`), they read `50 kg × 12` — plain, collapsed,
  exactly as before this chunk.
- Holding **pull ups**, they read `8 reps` — no expression, no `0 kg`, no dash.
- Holding **seated calf raise**, which the backfill deliberately left unset, they
  read `45 kg × 12` — exactly as they read yesterday.
- Holding **incline dumbbell press** (`0 / 2`), a 24 kg set reads
  `0 + 2 × 12 = 24 kg × 10`. That is AGREED 10, made with the consequence in
  view: it is not a bug, and it is not to be "fixed".
- A barbell movement logged below its own bar reads as a plain total with no
  expression.
- The **Earlier** lines under the comparison read the same way, comma-separated.
- **Completed exercises**, below the zone, reads the same way for every movement
  in the workout — different exercises in one list, each with its own loading.
- Editing a set still opens the same two boxes with the same numbers in them,
  and saving still works: this chunk changed nothing about entry.
- A reload shows the same thing.

## Do not

- Change `parseEntry`, the log-set form, the edit-set form, or any box the user
  types into — chunks 04 and 05.
- Store, send or persist a per-side number anywhere (AGREED 3).
- Round, tidy or "sensibly display" an uneven per-side weight (W3).
- Show `0 + 1 × 50` or `0 + 2 × 0` for anything, ever (AGREED 7, W9).
- Reinterpret a bodyweight set as a set of the bar (W9).
- Fetch the catalogue on any page that does not already fetch it — chunk 02 put
  the loading on the performed exercise precisely so that nothing has to.
- Touch `TrainingSessionDetail.jsx` — that is chunk 03.5, in one place.
- Change `Status.jsx`, `hooks.js` or `api.js`.
- Touch anything under `backend/`.

## What the user sees

**The current session tab starts showing its working.**

- A set of a barbell movement reads `20 + 2 × 45 = 110 kg × 5`. The number in
  the middle is the one the user actually put on the bar and the one they think
  in week to week; it has never been on this screen before.
- It reads that way in all three places the zone shows sets at once: this
  session's list, the **Last time** column beside it, and the **Earlier** lines
  underneath — so comparing this week to last week is comparing two numbers of
  the same kind.
- A stack or a sled — lat pulldown, leg press, a cable — still reads `50 kg × 12`.
  Nothing was gained by writing `0 + 1 × 50`, so nothing is written.
- A bodyweight set still reads `8 reps`, and a movement nobody has said anything
  about yet still reads exactly as it did.
- Below the zone, **Completed exercises** reads the same way, so the whole
  workout speaks one language.

What the user cannot do yet: **type** a per-side weight. The boxes still take
the total, so the expression is something the app shows back rather than
something it takes in. That is chunk 04. And a finished session's detail page
still shows bare totals — chunk 03.5.
