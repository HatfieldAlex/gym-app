# 03.5 — "That one is already here"

**Goal:** a name that is already in the catalogue stops being a failure and
becomes an answer: the entry that exists, named, and one tap away.

Needs chunks 02 and 03.0. Frontend only. This is the chunk that makes the
`existing` block chunk 02 put in the 400 body worth having.

## Read first

- `AddExerciseForm.jsx` and `ExerciseCatalogue.jsx` as chunk 03.0 left them
- [02-backend-api.md](02-backend-api.md), step 3 — the exact body a duplicate
  comes back as
- [api.js](../../frontend-web/src/api.js) — `ApiError`, its `.status`, `.data`
  and `.detail`
- [ExerciseDetail.jsx](../../frontend-web/src/pages/ExerciseDetail.jsx) — where a
  catalogue entry's own page lives, and the link shape that reaches it
- [00-context.md](00-context.md), assumption N5

## Build

1. **Three outcomes, not two.** `AddExerciseForm` currently knows *added* and
   *failed*. Split the failure: a 400 carrying `existing` is a **duplicate**, and
   it is neither of the other two. In the `catch`:

   ```js
   const existing = failure instanceof ApiError && failure.status === 400
     ? failure.data?.existing ?? null
     : null
   ```

   Optional chaining on `data` because a 500 or a dropped connection has none.

2. **The form hands the entry up, exactly as it hands up a created one.** A new
   optional prop, `onDuplicate(existing)`, called with the entry from the body.
   Then clear the box and leave focus in it, the same as a successful add — the
   user asked for that movement to be in the catalogue, and it is (N5). What was
   typed is not needed for a retry, because there is nothing to retry: the entry
   it named is on screen.

   When no `onDuplicate` is given, the form says it itself — `"Bench press" is
   already in the catalogue.` — as a plain `.status` line, **not** a
   `data-state="error"` one. Nothing went wrong. Chunk 04 passes a handler; the
   fallback is what keeps the component honest on its own.

3. **The other 400s speak for themselves.** A 400 *without* `existing` is a
   validation message chunk 02 wrote for a human — "A name is required.", or the
   length one. Show `failure.detail` in that case rather than the generic line.
   Everything else — 403, 500, a network failure — keeps chunk 03.0's "Could not
   add that exercise. Please try again."

   So: `existing` → step 2; 400 → the server's sentence; anything else → the
   generic line, retried with what is still in the box.

4. **The catalogue page answers with the row.** `ExerciseCatalogue.jsx` passes an
   `onDuplicate` that puts up a line under the form, beside where "Added …"
   goes and replacing it:

   > **Bench press** is already in the catalogue.

   with the name inside a `<Link>` pointing at `/exercises-catelog/` plus
   `existing.id` — the same link the table's rows use. The user typed a name to
   get a movement into the app; the movement is there, and this is the way to it.

   The entry is **not** inserted into the list: it is already in it. If the
   loaded list somehow lacks it — a page left open while it was added elsewhere —
   leave that alone too; a reload is the answer, and inventing a row here would
   put a duplicate on screen in the one flow that exists to prevent duplicates.

5. **The message names the stored spelling.** Render `existing.name`, never what
   was typed. Someone who typed `bench press` and is shown `bench press` learns
   nothing about why they could not find it; shown `Bench press`, they do.
   Catalogue names are user data — React escapes them, as the comment in
   `ExerciseCatalogue.jsx` already says.

6. **Style.** The duplicate line uses the existing `.status` class with no
   `data-state`, so it reads as neutral in both colour schemes without a new
   rule. If it needs anything beyond that, it goes in the
   `/* Add an exercise */` section chunk 03.0 opened.

## Done when

- With `Bench press` in the catalogue, typing `Bench press` and tapping Add:
  the box clears, no error styling appears, and a line under the form says
  **Bench press** is already in the catalogue, with the name linking to that
  entry's page.
- Typing `bench press`, `BENCH PRESS` or `Bench  press` gives the same line,
  naming `Bench press` — the stored spelling, not the typed one.
- The table gains no row in any of those cases, and the count above it does not
  change.
- Tapping the link lands on that exercise's detail page.
- A blank submit cannot happen (the button is disabled), but a name of 121
  characters shows the server's own message rather than the generic one.
- With the API failing outright, chunk 03.0's generic message still appears and
  the typed name is still in the box.
- A successful add still behaves exactly as chunk 03.0 left it.

## Do not

- Show a duplicate in red, or as an error (N5).
- Insert, highlight, re-sort or scroll to the existing row in the table (step 4).
- Re-fetch the catalogue to "check" the duplicate — the answer is in the response.
- Offer to rename, merge or replace the existing entry (N2).
- Suggest a name — "Bench press 2", "Bench press (variant)" — or otherwise help
  the user create a near-duplicate.
- Move the duplicate check into the browser by comparing against the loaded list.
  It would be a second rule to keep in step with chunk 02's, it would be wrong
  the moment someone else adds a movement, and the server has to check anyway.
- Touch `CurrentSession.jsx` — chunk 04.

## What the user sees

Adding something that is already there stops looking like a mistake.

- **No red, no "failed".** Type `bench press`, tap Add, and the app answers:
  **Bench press** is already in the catalogue — with the name as a link straight
  to it. The box clears, the way it does after any successful add, because what
  the user wanted is true.
- **The answer teaches the spelling.** It shows the catalogue's version of the
  name, which is usually why they could not find it: they were looking for
  `bench press` and the list says `Bench press`.
- **The list does not gain a second copy** — of anything, in any casing. That is
  the point of the whole exchange.
- **Real problems still read as problems.** A name that is too long says so, in
  the server's own words; a request that does not arrive says so, and keeps what
  was typed for another go.
